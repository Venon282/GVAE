# Architecture Decision Records

Each ADR captures one architectural decision and the reasoning behind it *at
the time it was made*. A changed decision gets a **new** ADR rather than an
edit to an old one in place (see the
[project specification](../global-vae-project-specification.md), §10).

Every ADR is also listed individually in the site sidebar, through
`docs/adr/SUMMARY.md` (mirroring how the changelog is navigated). Adding an ADR
means adding one row to the table below **and** one line to `SUMMARY.md`;
`tests/integration/test_docs_adr_navigation.py` fails if either is forgotten.

| [0020: Additional fusion strategies](0020-additional-fusion-strategies.md) | `moe` (closed-form moment matching), `concat_mlp` (explicit imputation plus presence mask) and `cross_attention` (one token per active modality) join `poe` in the fusion registry (spec §4, §5), with no change to `GlobalVae`. |
| [0021: Fusion residual connection](0021-fusion-residual-connection.md) | The `residual` flag of spec §4/§9, for every fusion strategy at once through one wrapper (`fusion.residual.ResidualFusion`): the fused posterior starts as the mean of the experts and a learned gate opens the strategy's correction. Off by default, per latent space. |
| [0022: Training callback registry](0022-callback-registry.md) | `training/callbacks/`: `TrainerCallback` (relocated), `CheckpointCallback`/`BestCheckpointCallback` (now one class per file) and the new `EarlyStopping`/`ReduceLrOnPlateau` self-register into one `training.callbacks` registry, selected from `TrainingConfig.callbacks` (registry name -> kwargs) instead of a hardcoded `CheckpointConfig` field; `Trainer.should_stop` is the new lever `EarlyStopping` uses. Experiment loggers (`training/loggers/`) keep their own, separate registry: a `Logger` is a journalling service, not a callback selection. |
| [0023: Snake_case module names](0023-snake-case-module-names.md) | The eight CamelCase encoder and decoder modules (`OneDCnnEncoder.py`, ...) are renamed to snake_case (`one_d_cnn_encoder.py`, ...), the old import paths stayed as warning shims until 2.0.0, where they were removed, and the CI lint job becomes blocking (roadmap D-9). |
| [0024: Encoder fan-out through latent heads](0024-encoder-fan-out-through-latent-heads.md) | `RoutingGraph.encoder_heads` (a `HeadSpec` per encoder -> latent edge), three new `validateRoutingGraph` rules, `GlobalVae` building and applying one head per edge before fusion, the `shared_private` preset taking head choices, and `AbstractAssembler.handlesMissingLatents` so a decoder with an incomplete `concat` input is skipped. Supersedes the fan-out guard of ADR 0002. |
| [0025: Config schema for several latent spaces](0025-config-schema-for-several-latent-spaces.md) | `encoders` and `decoders` sections keyed by instance name next to `modalities`, `latent_mode: several` with `latent.spaces` (`dim`, `fed_by` as a list or an `encoder -> {head, kwargs}` mapping, `fusion`, `regularizer`) and `latent.decoders_consume` (`spaces`, `assembler`, `kwargs`), widths derived rather than repeated, errors that name the field, `buildModelFromConfig` building a `RoutingGraph`. The default proposed for roadmap decision D-1. Supersedes the single-only part of ADR 0011. |
| [0026: Assembler constructor contract and learned assemblers](0026-assembler-constructor-contract-and-learned-assemblers.md) | Assemblers are built from `input_dims` and announce an `output_dim`, so `GlobalVae` checks or fills in each decoder's `latent_dim` at construction; `requires_matching_dims`, a class flag read through the registry, replaces the `{"sum", "average"}` set in `validateRoutingGraph`; `forward` gets `present` for a subset of the latent spaces; the new `weighted_sum` (softmax or raw per-space weights) and `attention` (learned-query cross-attention over per-space tokens) assemblers (roadmap P1-4, D-3). |
| [0027: Shared encoders and shared decoders](0027-shared-encoders-and-decoders.md) | `AbstractSharedEncoder` (receives `dict[str, Tensor]`, missing modalities omitted) and `AbstractSharedDecoder` (returns `dict[str, Tensor]`) in the existing encoder and decoder registries, so the `E1` and `D1` rows of spec §2.1 build; a batch key names an input modality, `GlobalVae.input_modalities` and `output_modalities` replace `encoders` and `decoders` wherever the code needs modality names, and the routing graph does not change (roadmap P1-5, decision D-2 option A). Supersedes the encoder-named-key rule of ADR 0019. |
| [0028: The learning rate in the metrics](0028-learning-rate-in-the-metrics.md) | `TrainerCallback.acts_on_learning_rate` (set by `ReduceLrOnPlateau`) makes `Trainer` record the rate in the step metrics (`lr`) and the epoch metrics (`train/lr`, `lr/group<i>` per parameter group), so it shows in the epoch log line, the loggers and the checkpoint history; runs without such a callback are unchanged. `plotLearningRate` and `scripts/visualize_latent.py` write `lr_curve.png` when the history holds a rate. |
| [0029: Loss scale convention](0029-loss-scale-convention.md) | States the objective's scale: the reconstruction term is a per-element mean while the KL is a per-sample sum, so `beta = 1` weights the KL `N / 2` times more than the usual ELBO (roadmap P2-1). `TrainingConfig.reconstruction_reduction` (`mean`, the default and unchanged, or `sum`, per modality) and `Trainer(reconstruction_reduction=...)` choose the scale, and the evaluation report gains latent diagnostics (the KL of each latent dimension and the active units). No empirical value of `beta`: that is roadmap decision D-6. |
| [0030: A reconstruction loss and weight per modality](0030-per-modality-reconstruction-loss-and-weight.md) | `TrainingConfig.reconstruction_loss` and `reconstruction_weight` take a single value or a decoder -> value mapping (roadmap P2-2). A decoder left out keeps `mse` and `1.0`; a bad name, a negative or non-finite weight or a key that is not a decoder of the model is an error that starts with the field's path. `scripts/evaluate.py` gains `--reconstruction-loss` and `--reconstruction-weight` and checks the decoder names of all three flags, so the report's total can match the training scale. Defaults unchanged. |
| [0031: Mixed precision, gradient accumulation and `torch.compile`](0031-mixed-precision-gradient-accumulation-and-compile.md) | `Trainer(mixed_precision=None | "bf16" | "fp16", accumulate_grad_batches=1, compile_model=False)` and the matching `TrainingConfig` fields, all off by default (roadmap P2-3). Autocast with `float32` losses and a gradient scaler for `fp16` (state saved in the checkpoint); a step becomes an optimizer update, so `global_step`, beta schedules, `onStepEnd` and `log_every_n_steps` count updates, with the partial last group rescaled to a mean; `torch.compile` wraps the forward pass without renaming `state_dict` keys. |
| [0032: Resuming a run from the training script](0032-resume-from-the-training-script.md) | `training.resume_from` and `resumeTrainerFromConfig`: `num_epochs` is the total of the run, so a finished run re-run does nothing; callbacks get `stateDict`/`loadStateDict` (plateau trackers, best and periodic checkpoints, top-K) stored in the checkpoint; `CsvLogger(append=...)` continues a metrics file on resume; a resumed deterministic run reproduces the uninterrupted loss curve to a relative `1e-6` (roadmap P2-3). |
| [0033: Top-K checkpoints and learning-rate schedules](0033-top-k-checkpoints-and-learning-rate-schedules.md) | Registered callbacks `top_k_checkpoint` (the `k` best epochs, each a full checkpoint, the worst evicted, state kept across a resume; the extension listed in ADR 0007), `linear_warmup_lr` and `cosine_lr` (closed-form functions of the optimizer step scaling the `initial_lr` of each parameter group, so a resume needs no schedule state and accumulation is exact; they feed the learning-rate metrics of ADR 0028) (roadmap P2-3). |
| [0034: Safe checkpoint loading by default](0034-safe-checkpoint-loading-by-default.md) | `loadCheckpoint` and `Trainer.loadCheckpoint` read with `torch.load(weights_only=True)` by default, which a checkpoint now allows (the NumPy RNG state is a list, a dataclass `config` is stored as a dict). A file from an earlier version is refused with an error naming `upgradeCheckpoint`, `weights_only=False` and the new `--trust-checkpoint` flag of `scripts/evaluate.py` and `scripts/visualize_latent.py` (roadmap P2-3; a change of behavior for old files). |
| [0035: An MLflow experiment logger](0035-mlflow-experiment-logger.md) | `MlflowLogger`, registered as `mlflow` (roadmap P2-4, decision D-8 at its proposed default): an optional `mlflow` extra with the import deferred as for TensorBoard, an explicit `MlflowClient` and run id instead of the fluent API, one `log_batch` request per step, figures as `figures/<name>/<tag>_<x>.png`, images through `log_image` (floats clipped to `[0, 1]`), the run ending `FINISHED`, `FAILED` or `KILLED` and staying writable, and an offline mode that is a SQLite store (MLflow 3 refuses the `./mlruns` file store). No change to `Trainer` or the config schema. |
| [0036: When to migrate the training loop to Lightning or Fabric](0036-lightning-migration-triggers.md) | Two checkable triggers, both needed (roadmap P2-5): Phase 1 complete (met, `test_configuration_matrix.py` passes 8 of 8) and a measured need for more than one GPU on real data or a real backbone, after the shipped levers (not met: no real run exists). What a migration must keep: the config, the `TrainerCallback` seam through one adapter, the checkpoint file and the ADR 0032 resume guarantee, the caller's `loader_factory`. Fabric first, as spec §10's intermediate step. No code changes. |
| [0037: Transformer and ViT backbones](0037-transformer-and-vit-backbones.md) | Six registered classes (`1d_transformer_*`, `2d_vit_*`, `shared_transformer_*`) and `utils/transformer_blocks.py`, with zero core changes (roadmap P3-5): patches cut by a strided convolution with edge padding and a cropped output, sinusoidal positions by default (length-agnostic) or learned, pre-norm encoders with a `[CLS]` or mean pool, decoders whose tokens are positions plus the projected latent vector, and the first shared backbone (one token stream for a series and an image, a missing modality is a shorter stream). `cross_attention` keeps its two-token scale (a fusion sees `(mu, logvar)`, not patches). Four experiments set `sum` at 0.5, with measurements. Finding: for a shared decoder the loss settings are keyed by decoder name in the config layer and by modality in the loss, so a mapping is ignored or raises `KeyError`. |
| [0038: Paired-data evaluation](0038-paired-data-evaluation.md) | Opt-in `evaluation/` modules and `scripts/evaluate.py` flags, with no core change (roadmap P3-6): a modality-specific posterior mean is the `mu` of a latent space when the model is queried with one modality alone; retrieval (`recall@k` next to `chance_recall@k`, mean and median rank, MRR, cosine or `l2`, chunked, ties counted as a random order so a collapsed latent scores exactly chance) and closed-form alignment (paired against mismatched cosine and distance, per-dimension correlation) in `paired_alignment.py`; a per-modality `MetricsTable` (`.md`, `.csv`, `.json`); and streaming `mse`, `rmse`, `mae`, `r2` and `pearson_r` (all five, not three: they are functions of running moments, merged in `float64`), used by `evaluate(streaming=True)`. A recall is read against its chance level. |
| [0039: The tabular modality](0039-tabular-modality.md) | Two registered classes (`tabular_mlp_encoder_v1`, `tabular_mlp_decoder_v1`) and `utils/mlp_blocks.py`, with zero core changes (roadmap P3-8, first modality): a row is one flat float vector `(batch, num_features)` built by the caller's `loader_factory` (numeric columns standardized, then one-hot blocks), missing values are imputed by the caller (a `NaN` makes the row `NaN`), the decoder takes optional `categorical_sizes` and applies a softmax inside each one-hot block so the default `mse` is the Brier score of a categorical column, and an MLP configured by name (widths, activation, `layer` or `batch` normalization, dropout). The experiment sets `sum` at 0.5, with measurements (`mean` collapses, as for the signal and image). Findings: one loss per decoder (no per-column loss), no output variance, and YAML cannot write the per-column statistics `standardize` needs. |
| [0040: The audio modality](0040-audio-modality.md) | Two registered classes (`audio_waveform_encoder_v1`, `audio_waveform_decoder_v1`), `utils/waveform_blocks.py` and `utils/activations.py` (moved out of `mlp_blocks.py`), with zero core changes (roadmap P3-8, second modality): the 1D classes were not enough for a waveform (the decoder must reach `output_length` exactly, no bounded output, one dilation per stage), so the pair uses dilated residual units and strided convolutions whose lengths are exact (`ceil(L / s)` down, `s` times up), a decoder that crops a rounded-up seed to any `output_length`, and a `tanh` output; the loader makes the clip (float, within [-1, 1], one rate, one length); a spectrogram is an image and needs no new class. The experiment sets `sum` at 0.5, with measurements (`mean` collapses). Findings: one latent per clip, no spectral loss from YAML, no sample rate in the data contract. |
| [0041: The text modality](0041-text-modality.md) | Two registered classes (`text_transformer_encoder_v1`, `text_transformer_decoder_v1`) and `utils/text_blocks.py`, with zero core changes (roadmap P3-8, third modality): the loss demands a target of the reconstruction's shape, so a text is a one-hot tensor `(batch, length, vocab_size)` made by the caller, and the decoder returns a distribution over the vocabulary at each position; the encoder reads ids or one-hot rows with identical output and skips a padding token, so padding does not change a latent vector; the decoder writes the whole text in one pass (no autoregression, so no posterior collapse); `bce` summed with weight 2.0 from YAML and an exact cross-entropy (`computeTokenCrossEntropy`) from Python, measured on a synthetic language where the weight is the lever (87% of tokens at 1.0, 99% at 2.0, 100% at 4.0) and the 1D transformer pair reaches 62 to 65%; findings, not fixed: no cross-entropy in the loss table, ids cannot be targets (a one-hot batch costs `batch * length * vocab_size` floats), one latent per text, no vocabulary field in `DataConfig`. |
| [0042: The time series modality](0042-time-series-modality.md) | One registered class (`time_series_encoder_v1`) and `utils/series_blocks.py`, with zero core changes and the existing `1d_cnn_decoder_v1` reused (roadmap P3-8, fourth modality, and the model side of P3-7): a `NaN` in the batch tensor is a value that was not observed, a gap or the padding of a short series, because the batch tensor is the only thing both the encoder and the loss read; the encoder feeds values and the observed mask, skips empty patches, and gives the same latent vector for a series padded with `NaN`; `computeMaskedSquaredError` is the Python route for series with gaps, since the `mse` of a YAML file is `NaN` on a gap; measured on synthetic series where the CNN decoder beat the transformer decoder (0.80 against 0.53), the new encoder matched a zero-filled CNN encoder on observed values and gaps and led by 0.20 on the steps after a short recording, and the weight was flat from 5 to 500; findings: no mask in the loss table, `NaN` evaluation metrics, one latent per window, no per-window normalization. |
| [0043: The graph modality](0043-graph-modality.md) | One registered decoder (`graph_cnn_decoder_v1`, a thin subclass of the 2D CNN decoder) and `utils/graph_metrics.py`, with zero core changes and the existing `2d_cnn_encoder_v1` reused (roadmap P3-8, fifth modality): a graph is a dense adjacency matrix `(batch, N, N)` padded with isolated nodes (zeros, since the registered encoder turns a `NaN` into a `NaN` latent vector), which is an image to the 2D classes; the decoder symmetrizes, applies a sigmoid and zeroes the diagonal so that `bce` with `sum` (weight 4.0) is the Bernoulli likelihood of the edges and runs from YAML, which is why the class exists and not for accuracy; measured on synthetic graphs where every graph-specific design (message passing, one token per node, an MLP decoder) was worse than the registered pair (AUC 0.903 against 0.838 to 0.893 at weight 1), `bce` beat `mse` by about 0.01, and node order moved the AUC by 0.10 to 0.16, at least as much as the whole choice of architecture, with no encoder able to remove it; findings, not fixed: no matching loss, no logits `bce` in the loss table, entry-wise `evaluate` metrics, no number of nodes, no node features, dense `N^2` memory, one latent per graph. |
| [0044: The point cloud modality](0044-point-cloud-modality.md) | One registered encoder (`point_cloud_encoder_v1`, a PointNet-style pooling that is exactly invariant to the order of the points and to `NaN` padding) and one registered decoder (`point_cloud_decoder_v1`, a folding of a learned template, any `num_points`), `utils/point_cloud_blocks.py` and `utils/point_cloud_metrics.py`, with zero core changes (roadmap P3-8, sixth and last modality): a cloud is a set `(batch, N, 3)` where a row of `NaN` is a point that does not exist; the order-free loss is the Chamfer distance, a Python function the trainer accepts (`reduction="mean"`, weight 100.0, a `1 / w` beta by D-6), because every loss a YAML file can name pairs unrelated points and trained a model several times worse than a cloud that ignores its input (Chamfer 0.81 and 0.39 against 0.10), so the experiment file is a composed config with a placeholder loss and a warning; measured on synthetic clouds, the registered 1D transformer encoder and 1D CNN decoder are within 4 percent at 64 points and equal at 128, so the classes are justified by exact invariance, the `NaN` convention and cost (3 to 12 times faster than the attention encoder), not by accuracy; flagged and not fixed: no set loss in the loss table, the trainer refuses different numbers of points, the metrics of `evaluate` are position by position, the Chamfer loss is quadratic in `N` |
| [0045: Loss settings are keyed by reconstruction name](0045-settings-keyed-by-reconstruction-name.md) | `reconstruction_loss`, `reconstruction_weight` and `reconstruction_reduction` mappings are keyed by the name of a reconstruction (a decoder of one modality, or each modality of a shared decoder), not by decoder name, so a signal and an image of one shared decoder can take different values; the name of a shared decoder is refused, with both lists of names in the error |
| [0046: Encode and decode seams](0046-encode-and-decode-seams.md) | `GlobalVae.encode(inputs, use_mean=False)` runs the encoders, heads, fusion and sampling and stops at the latent spaces (typed `EncodeOutput`: `latent_params`, `latent_samples`), `GlobalVae.decode(latent_samples)` runs the assemblers and the decoders with the missing-latent rules of `forward`, and `forward` becomes `encode` then `decode` with the same three keys, the same error messages and the same order of random draws, so a fixed seed gives the 2.0.0 tensors bit for bit (roadmap P5-5); cross decoding is a calling convention, not a method (`decode({"z_image": samples["z_signal"]})`, equal widths, a clear error otherwise), and `collectModalityPosteriorMeans` switches to `encode`, so a paired retrieval calls no decoder and no assembler (a test counts the calls) and a query is 1.3 to 2.9 times faster on the shipped signal and image configs; flagged and not fixed: a width that matches by chance is not a latent space that matches by meaning, which is the training of Phase 6 |
| [0047: Extra loss terms at the single loss site](0047-extra-loss-terms.md) | A registry `losses/terms/` (`AbstractLossTerm`, an `nn.Module` whose `forward(model, batch, outputs, step)` returns a scalar; `registerLossTerm`, `getLossTermClass`, `listRegisteredLossTerms`; it ships empty, the terms being the objectives of Phases 6 and 7), `training.loss_terms` as a list of `{name, weight, schedule, kwargs}` (the weight is a number or a registered beta schedule, never both), `StepLosses.terms` (each term after its weight, added to the total and logged as `loss/<name>`, so `train/loss/<name>` and `val/loss/<name>`, a deliberate reading of the roadmap's `train/<name>` that keeps the family of `loss/total`), and the parameters of a term held by the trainer: in the one optimizer group, clipped with the model's, saved under `loss_terms_state_dict` (a key of its own, absent for a run without term) and restored by `resume_from` under the guarantee of ADR 0032, with a clear error when the terms differ; computed in `float32` and scaled by the accumulation like the total, and a run without term is the 2.0.0 run bit for bit (a copy of the old `computeLosses` is kept in the tests) (roadmap P5-6); flagged and not fixed: a term that decodes runs in `float32` under mixed precision, and the specification's lists of registries do not name this one yet, a proposal for the owner |
| [0048: Reconstruction loss and metric registries](0048-reconstruction-loss-and-metric-registries.md) | The reconstruction loss leaves the fixed table of `config/training.py`: `losses/reconstruction/` is a package with `AbstractReconstructionLoss` (an `nn.Module`, so a loss can own parameters, which the trainer holds in `Trainer.reconstruction_losses`, puts in the optimizer, clips, and saves under `reconstruction_loss_state_dict`, a key of its own that a run with the four classic losses never writes), a registry (`registerReconstructionLoss`, `getReconstructionLossClass`, `listRegisteredReconstructionLosses`, the twelfth registry of `test_registry_contract.py`) and three class-level declarations read through it (`requires_matching_shapes`, `reads_nan_as_unobserved`, `countTerms`, which `sum` multiplies by, so a loss is always a mean over its terms, ADR 0029);
