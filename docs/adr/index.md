# Architecture Decision Records

Each ADR captures one architectural decision and the reasoning behind it *at
the time it was made*. A changed decision gets a **new** ADR rather than an
edit to an old one in place (see the
[project specification](../global-vae-project-specification.md), §10).

Every ADR is also listed individually in the site sidebar, through
`docs/adr/SUMMARY.md` (mirroring how the changelog is navigated). Adding an ADR
means adding one row to the table below **and** one line to `SUMMARY.md`;
`tests/integration/test_docs_adr_navigation.py` fails if either is forgotten.

| ADR | Topic |
|---|---|
| [0001: Phase 1 default configuration](0001-phase1-default-configuration.md) | Why `EN-L1-DN` (per-modality encoders, one fused latent, per-modality decoders) is the recommended Phase-1 default among the 8 valid configurations (spec §2.1). |
| [0002: Generalizing GlobalVae to a routing graph](0002-generalize-global-vae-to-routing-graph.md) | Building `GlobalVae` from an explicit `RoutingGraph` instead of a fixed shared/private split; documents the current encoder fan-out limitation. |
| [0003: Pluggable latent regularization](0003-pluggable-latent-regularization.md) | Moving KL-to-standard-normal out of the model class and into a registry (`AbstractLatentRegularizer`), so MMD / free-bits / learned priors can be swapped in per latent space. |
| [0004: Pluggable beta schedules](0004-pluggable-beta-schedules.md) | Beta-weighting schedules (constant, linear warm-up, cyclical annealing) as a strategy orthogonal to which regularizer is used. |
| [0005: Training loop](0005-training-loop.md) | Choosing a raw PyTorch loop (`Trainer`) over Lightning for now, migrating later once the architecture stabilizes. |
| [0006: Reproducibility (seed and checkpointing)](0006-reproducibility-seed-and-checkpointing.md) | Global seed management, a documented deterministic-mode flag, and checkpoint save/restore. |
| [0007: Best-checkpoint callback](0007-best-checkpoint-callback.md) | Why `BestCheckpointCallback` (saves on metric improvement) is a separate callback from `CheckpointCallback` (saves on a schedule, for resuming). |
| [0008: Experiment loggers](0008-experiment-loggers.md) | `AbstractExperimentLogger` as a `TrainerCallback`, so CSV/TensorBoard backends need no `Trainer` changes to support, and several can run at once. |
| [0009: Visualization](0009-visualization.md) | The `visualization/` subpackage: latent-space projections/plots, reconstruction overlays, loss curves. |
| [0010: Evaluation](0010-evaluation.md) | A standalone evaluation pass (`evaluate()`), distinct from training, needing only a model and a dataloader. |
| [0011: Hydra config layer](0011-hydra-config-layer.md) | The `global_vae.config` package: dataclass-validated `ModelConfig` / `DataConfig` / `TrainingConfig` / `ExperimentConfig`. |
| [0012: Generic data transforms](0012-generic-data-transforms.md) | `data/transforms/`: `log` / `standardize` / `resample` as dimensionality-agnostic, invertible, registry-based transforms. |
| [0013: Coordinate-aware resampling](0013-coordinate-aware-resampling.md) | `ResampleTransform`'s `interpolation="scipy"` mode: explicit source/target positions, not just point counts. |
| [0014: Residual 1D encoder/decoder](0014-residual-1d-encoder-decoder.md) | `OneDCnnResidualEncoder` / `OneDCnnResidualDecoder`: configurable-depth residual blocks as an alternative backbone (spec §7). |
| [0015: Per-modality data transforms](0015-per-modality-data-transforms.md) | `DataConfig.transforms` and `sequence_length` become per-modality mappings (modality name to steps/length), and `buildTransformPipeline` returns one invertible pipeline per modality, so two datasets sharing an encoder/decoder family can each have their own preprocessing (spec §6). |
| [0016: Cross-modal reconstruction reporting](0016-cross-modal-reconstruction-reporting.md) | Running a trained model under several input-modality subsets and laying out what every decoder reconstructs (`collectCrossModalReconstructions`, `evaluation/cross_modal.py`), with no change to `GlobalVae.forward` (spec §5). |
| [0017: 2D CNN encoder/decoder](0017-2d-cnn-encoder-decoder.md) | `TwoDCnnEncoder` / `TwoDCnnDecoder` for the image modality (spec §6), plus the `list`-means-per-stage / `tuple`-means-shared convention for shape-like hyperparameters (`broadcastPerStageShape`). |
| [0018: 2D residual encoder/decoder](0018-2d-residual-encoder-decoder.md) | `TwoDCnnResidualEncoder` / `TwoDCnnResidualDecoder` built from `Residual2DBlock` / `Residual2DUpBlock`: the 2D generalization of ADR 0014, with the residual shortcut verified per axis (spec §7). |
| [0019: Decouple encoder inputs from decoder targets](0019-decouple-encoder-inputs-from-decoder-targets.md) | `GlobalVae.selectEncoderInputs` restricts a raw batch to encoder-named keys before every framework forward pass, so a decoder target need not also be an encoder input (a translation-style model); `Trainer.evaluate` never applies modality dropout. |
| [0020: Additional fusion strategies](0020-additional-fusion-strategies.md) | `moe` (closed-form moment matching), `concat_mlp` (explicit imputation plus presence mask) and `cross_attention` (one token per active modality) join `poe` in the fusion registry (spec §4, §5), with no change to `GlobalVae`. |
| [0021: Fusion residual connection](0021-fusion-residual-connection.md) | The `residual` flag of spec §4/§9, for every fusion strategy at once through one wrapper (`fusion.residual.ResidualFusion`): the fused posterior starts as the mean of the experts and a learned gate opens the strategy's correction. Off by default, per latent space. |
| [0022: Training callback registry](0022-callback-registry.md) | `training/callbacks/`: `TrainerCallback` (relocated), `CheckpointCallback`/`BestCheckpointCallback` (now one class per file) and the new `EarlyStopping`/`ReduceLrOnPlateau` self-register into one `training.callbacks` registry, selected from `TrainingConfig.callbacks` (registry name -> kwargs) instead of a hardcoded `CheckpointConfig` field; `Trainer.should_stop` is the new lever `EarlyStopping` uses. Experiment loggers (`training/loggers/`) keep their own, separate registry: a `Logger` is a journalling service, not a callback selection. |
| [0023: Snake_case module names](0023-snake-case-module-names.md) | The eight CamelCase encoder and decoder modules (`OneDCnnEncoder.py`, ...) are renamed to snake_case (`one_d_cnn_encoder.py`, ...), the old import paths stay as warning shims until 2.0, and the CI lint job becomes blocking (roadmap D-9). |
| [0024: Encoder fan-out through latent heads](0024-encoder-fan-out-through-latent-heads.md) | `RoutingGraph.encoder_heads` (a `HeadSpec` per encoder -> latent edge), three new `validateRoutingGraph` rules, `GlobalVae` building and applying one head per edge before fusion, the `shared_private` preset taking head choices, and `AbstractAssembler.handlesMissingLatents` so a decoder with an incomplete `concat` input is skipped. Supersedes the fan-out guard of ADR 0002. |
| [0025: Config schema for several latent spaces](0025-config-schema-for-several-latent-spaces.md) | `encoders` and `decoders` sections keyed by instance name next to `modalities`, `latent_mode: several` with `latent.spaces` (`dim`, `fed_by` as a list or an `encoder -> {head, kwargs}` mapping, `fusion`, `regularizer`) and `latent.decoders_consume` (`spaces`, `assembler`, `kwargs`), widths derived rather than repeated, errors that name the field, `buildModelFromConfig` building a `RoutingGraph`. The default proposed for roadmap decision D-1. Supersedes the single-only part of ADR 0011. |
| [0026: Assembler constructor contract and learned assemblers](0026-assembler-constructor-contract-and-learned-assemblers.md) | Assemblers are built from `input_dims` and announce an `output_dim`, so `GlobalVae` checks or fills in each decoder's `latent_dim` at construction; `requires_matching_dims`, a class flag read through the registry, replaces the `{"sum", "average"}` set in `validateRoutingGraph`; `forward` gets `present` for a subset of the latent spaces; the new `weighted_sum` (softmax or raw per-space weights) and `attention` (learned-query cross-attention over per-space tokens) assemblers (roadmap P1-4, D-3). |
| [0027: Shared encoders and shared decoders](0027-shared-encoders-and-decoders.md) | `AbstractSharedEncoder` (receives `dict[str, Tensor]`, missing modalities omitted) and `AbstractSharedDecoder` (returns `dict[str, Tensor]`) in the existing encoder and decoder registries, so the `E1` and `D1` rows of spec §2.1 build; a batch key names an input modality, `GlobalVae.input_modalities` and `output_modalities` replace `encoders` and `decoders` wherever the code needs modality names, and the routing graph does not change (roadmap P1-5, decision D-2 option A). Supersedes the encoder-named-key rule of ADR 0019. |
| [0028: The learning rate in the metrics](0028-learning-rate-in-the-metrics.md) | `TrainerCallback.acts_on_learning_rate` (set by `ReduceLrOnPlateau`) makes `Trainer` record the rate in the step metrics (`lr`) and the epoch metrics (`train/lr`, `lr/group<i>` per parameter group), so it shows in the epoch log line, the loggers and the checkpoint history; runs without such a callback are unchanged. `plotLearningRate` and `scripts/visualize_latent.py` write `lr_curve.png` when the history holds a rate. |
| [0029: Loss scale convention](0029-loss-scale-convention.md) | States the objective's scale: the reconstruction term is a per-element mean while the KL is a per-sample sum, so `beta = 1` weights the KL `N / 2` times more than the usual ELBO (roadmap P2-1). `TrainingConfig.reconstruction_reduction` (`mean`, the default and unchanged, or `sum`, per modality) and `Trainer(reconstruction_reduction=...)` choose the scale, and the evaluation report gains latent diagnostics (the KL of each latent dimension and the active units). No empirical value of `beta`: that is roadmap decision D-6. |
| [0030: A reconstruction loss and weight per modality](0030-per-modality-reconstruction-loss-and-weight.md) | `TrainingConfig.reconstruction_loss` and `reconstruction_weight` take a single value or a decoder -> value mapping (roadmap P2-2). A decoder left out keeps `mse` and `1.0`; a bad name, a negative or non-finite weight or a key that is not a decoder of the model is an error that starts with the field's path. `scripts/evaluate.py` gains `--reconstruction-loss` and `--reconstruction-weight` and checks the decoder names of all three flags, so the report's total can match the training scale. Defaults unchanged. |
| [0031: Mixed precision, gradient accumulation and `torch.compile`](0031-mixed-precision-gradient-accumulation-and-compile.md) | `Trainer(mixed_precision=None | "bf16" | "fp16", accumulate_grad_batches=1, compile_model=False)` and the matching `TrainingConfig` fields, all off by default (roadmap P2-3). Autocast with `float32` losses and a gradient scaler for `fp16` (state saved in the checkpoint); a step becomes an optimizer update, so `global_step`, beta schedules, `onStepEnd` and `log_every_n_steps` count updates, with the partial last group rescaled to a mean; `torch.compile` wraps the forward pass without renaming `state_dict` keys. |
| [0032: Resuming a run from the training script](0032-resume-from-the-training-script.md) | `training.resume_from` and `resumeTrainerFromConfig`: `num_epochs` is the total of the run, so a finished run re-run does nothing; callbacks get `stateDict`/`loadStateDict` (plateau trackers, best and periodic checkpoints, top-K) stored in the checkpoint; `CsvLogger(append=...)` continues a metrics file on resume; a resumed deterministic run reproduces the uninterrupted loss curve to a relative `1e-6` (roadmap P2-3). |
| [0033: Top-K checkpoints and learning-rate schedules](0033-top-k-checkpoints-and-learning-rate-schedules.md) | Registered callbacks `top_k_checkpoint` (the `k` best epochs, each a full checkpoint, the worst evicted, state kept across a resume; the extension listed in ADR 0007), `linear_warmup_lr` and `cosine_lr` (closed-form functions of the optimizer step scaling the `initial_lr` of each parameter group, so a resume needs no schedule state and accumulation is exact; they feed the learning-rate metrics of ADR 0028) (roadmap P2-3). |
| [0034: Safe checkpoint loading by default](0034-safe-checkpoint-loading-by-default.md) | `loadCheckpoint` and `Trainer.loadCheckpoint` read with `torch.load(weights_only=True)` by default, which a checkpoint now allows (the NumPy RNG state is a list, a dataclass `config` is stored as a dict). A file from an earlier version is refused with an error naming `upgradeCheckpoint`, `weights_only=False` and the new `--trust-checkpoint` flag of `scripts/evaluate.py` and `scripts/visualize_latent.py` (roadmap P2-3; a change of behavior for old files). |
| [0035: An MLflow experiment logger](0035-mlflow-experiment-logger.md) | `MlflowLogger`, registered as `mlflow` (roadmap P2-4, decision D-8 at its proposed default): an optional `mlflow` extra with the import deferred as for TensorBoard, an explicit `MlflowClient` and run id instead of the fluent API, one `log_batch` request per step, figures as `figures/<name>/<tag>_<x>.png`, images through `log_image` (floats clipped to `[0, 1]`), the run ending `FINISHED`, `FAILED` or `KILLED` and staying writable, and an offline mode that is a SQLite store (MLflow 3 refuses the `./mlruns` file store). No change to `Trainer` or the config schema. |
| [0036: When to migrate the training loop to Lightning or Fabric](0036-lightning-migration-triggers.md) | Two checkable triggers, both needed (roadmap P2-5): Phase 1 complete (met, `test_configuration_matrix.py` passes 8 of 8) and a measured need for more than one GPU on real data or a real backbone, after the shipped levers (not met: no real run exists). What a migration must keep: the config, the `TrainerCallback` seam through one adapter, the checkpoint file and the ADR 0032 resume guarantee, the caller's `loader_factory`. Fabric first, as spec §10's intermediate step. No code changes. |
